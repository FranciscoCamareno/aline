## Architecture

Client-side modular monolith; no app server. Layering is enforced by `no-restricted-imports` in `eslint.config.js`:

- `domain/` — pure types/rules (Revision zod schema, frontmatter, tags, sidecar). No React/Dexie/Excalidraw.
- `ports/` + `application/` — only depend on domain/shared and port interfaces. `VaultService` is the single entry point for content changes (create/open/save note & canvas, rename).
- `adapters/` — `indexeddb` (Dexie), `excalidraw` (scene codec), `zip`, `filesystem` (folder `RemoteStore`), `drive` (`driveApi.ts` fetch client + error mapping, `DriveRemoteStore`, `GoogleAuth`).
- `features/` + `app/` — React UI; must not import drive/filesystem adapters. `app/services.ts` is the composition root.

### Revision model (the core invariant)

Content is never mutated in place. Every save is a new immutable `Revision` with `parentIds` = heads the editor knew about, `contentRefs` pointing to SHA-256-addressed blobs. `DexieVaultRepository.commit` does, in **one Dexie transaction**: insert blobs (idempotent by hash), verify all referenced blobs exist, add revision, update `documents.headRevisionIds`, add `historyIndex` and `outbox` entries. If the stored heads ≠ `knownHeads`, the new revision becomes an extra head and the result is `status: 'conflict'` — never overwrite. Don't `await` non-Dexie promises (e.g. `crypto.subtle`) inside the transaction; hash beforehand.

`VaultService` keeps one shared `EditSession` per document (editor and rename share it) and a per-document write queue (`serialized`), and `open*` waits on pending writes. When a doc has multiple heads, the session tracks only the opened head so a save never silently merges a conflict.

Notes: stored blob = frontmatter (`schema_version`, `id`, `title`, `tags`, unknown keys preserved) + body; the editor only sees the body, and frontmatter is re-serialized from revision metadata on every save/rename. Hashes are over exact UTF-8 bytes.

Canvas: the application treats scenes as opaque `.excalidraw` JSON. `adapters/excalidraw/sceneCodec.ts` serializes with Excalidraw's `serializeAsJSON(..., 'local')`, replaces each file `dataURL` with `mindnote-asset:<sha256>` (bytes stored as separate blobs) and reverses it on load. `contentSignature` makes scroll/zoom/selection changes not produce revisions. The canvas sidecar (`domain/sidecar.ts`) is created and carried forward unchanged; it is the future authority for links/branches — don't put product data only in Excalidraw `customData`.

Autosave (`app/useAutosave.ts` + `shared/coalesce.ts`): 500 ms debounce, 2 s max wait, flush on pointerup (deferred 50 ms because Excalidraw's last onChange follows pointerup), visibilitychange/pagehide and unmount. UI shows "Guardado en este dispositivo" only after the transaction commits; never "Sincronizado" for a local write.

Read compatibility (`domain/compat.ts`): `open*` sets `EditSession.readOnly` when a revision, note frontmatter, sidecar or scene has a newer version than supported or fails its schema; save/rename then throw `unsupported-version` and the views render read-only. Never "upgrade" or rewrite such content.

Process-level glue lives in `app/runtime.ts`: `logDiagnostic` (local, size-rotated log in the `diagnostics` table — never note text or tokens; pass errors through `describeError`) and `registerFlusher`/`flushAllWrites`, which the PWA update prompt awaits (plus `VaultService.whenIdle` and terminating the hash worker) before activating a new service worker. Hashing in `shared/hash.ts` is pluggable: the app installs the worker client (`workers/hashClient.ts`, worker only above 16 KB); unit tests use Web Crypto. If IndexedDB can't open, `StartupError` offers a temporary in-memory vault (`fake-indexeddb`, a runtime dependency loaded only on that path).

Open format & backups: `application/vaultFormat.ts` turns `VaultContent` into the `vault/` file tree and back (`filesToVault` verifies hashes, keeps newer-version revisions for read-only, drops revisions with missing/corrupt objects or retired by controls, and recomputes heads from `parentIds`). `application/backup.ts` adds/verifies `backup-manifest.json`; ZIP runs in `workers/zip.worker.ts` via the `Archiver` port with path and size limits (`adapters/zip`). Restores always go into a NEW database registered in `adapters/indexeddb/registry.ts` (one IndexedDB per vault; the original is `mindnote-vault`) and are compared byte-for-byte before being offered. Operations that rewrite a head from the UI (restore version, resolve conflict, trash) must `flushAllWrites()` first and then remount the view (App's per-document reload counter), otherwise an editor's pending autosave would overwrite them. While Excalidraw has `appState.newElement`, CanvasView writes a stroke draft (device preference `draft:<docId>`) instead of revisions.

Knowledge layer: `application/knowledge.ts` extracts links/text (notes via the remark AST — never regex over raw Markdown; canvases from scene JSON + sidecar). `KnowledgeService` maintains the derived `linkIndex`/`searchDocuments` tables per document and resolves `[[Title]]` at query time (unique title only). `app/knowledgeRuntime.ts` reindexes after every `VaultService.onCommit` (so every command that commits must notify listeners — there is a unit test for this) and drives the MiniSearch worker, which loads `searchDocuments` directly from IndexedDB to keep the main thread free. Canvas sidecar (`elementLinks`, `danglingConnectorIds`) is re-derived on every canvas save by `adapters/excalidraw/sidecar.ts`; element links use the engine's `element.link` with `aline://document/<id>[#element]`, intercepted in `onLinkOpen`. Internal links are parsed/built only via `domain/links.ts` (writes `aline://`, still reads legacy `mindnote://` — never rewrite old links); fragments `b=`/`ev=`/`t=` and text anchors (`domain/anchors.ts`, quotes over displayed text, not Markdown source) are spec format §2.3.1, plan phase 7. Text editors link the selection through `features/knowledge/useSelectionLinker.tsx` (button + Ctrl/⌘+K, `LinkPicker` offers every `isLinkableKind` document, calendar events and — plan 10.6, `CanvasStep.tsx` — canvas elements listed by the pure `application/canvasTargets.ts` with a clickable `features/canvas/CanvasPreview.tsx` (`exportToSvg` + an overlay sharing its viewBox; classes `canvas-shot*`, since `.canvas-preview` belongs to the history preview); pickers and previews read with `VaultService.readCanvas/readCalendar`, which open no edit session); Milkdown's link schema is extended (`linkKeepingInternal`) because its sanitizer blanks non-http `href`s; following an `ev=` link goes to the calendar section without changing `activeId`. The knowledge index covers every `isLinkableKind` document (calendars via `extractCalendar`, events as search `elements`); `StoredLink` carries the target anchor and the source `context`, anchor status (`approximate`/`anchor-lost`) is computed at query time against the target's indexed text (`SearchDocument.text` is the displayed text, `blocks` the anchored blocks), so sources need no reindex when a target changes; bump `KNOWLEDGE_INDEX_FORMAT` when derived data changes shape (sync then rebuilds everything; 3 since plan 10.6: canvases index `elementIds`, so a link to a deleted element is `anchor-lost`); rich and Markdown docs have a links panel (`features/docs/LinksPanel.tsx`, plan 10.5: list from the open editor via `docLinks.ts` `liveLinks`/`jsonLinks` for other tabs, status from `KnowledgeService.outgoing`, previews in `features/knowledge/LinkPreview.tsx` that never touch the network); canvas sidecar `elementLinks[id].fragment` holds non-element anchors. Fragments with backlinks are highlighted with editor decorations only (`features/knowledge/backlinkMarks.ts` → `notes/backlinkMarksCm.ts`, `docs/backlinkMarksPm.ts`; one ProseMirror plugin per editor because Tiptap and Milkdown ship separate ProseMirror copies whose classes can't be mixed); views receive `knowledge` from App. Calendar events carry optional `links` (`eventLinkSchema`: internal or http(s) only, max 50); `EventDialog` saves pending edits before following one. Navigation to a document/element/text goes through `useUiStore().navigate`; CanvasView applies the focus only once the element exists (the engine API arrives before the scene). Folders are documents with `kind: 'folder'`; never cascade deletes.

Sync: `application/SyncEngine.ts` is destination-agnostic and talks to the `RemoteStore` port (`adapters/filesystem/FolderRemoteStore.ts` and `adapters/drive/DriveRemoteStore.ts`). Cycle: check vaultId (mismatch → `VaultMismatchError`, never mix vaults) → publish local controls → pull ids, verify every object by SHA-256 in staging, activate via `DexieSyncStore.applyRemote` (heads recomputed from `parentIds`; divergence stays as multiple heads) → import external edits of `readable/` copies → push unpublished revisions (objects first, revision last; idempotent by id; publication marks per target in `remoteFiles`). Retired revisions (any control) are never re-downloaded. `app/syncRuntime.ts` owns the single binding per vault (device preference `binding`, `kind: 'folder' | 'drive'`; sync target = `folder` or `drive:<folderId>`, so marks/cursors are per destination folder) and triggers. Folder permission is revalidated on start; Drive starts in `needs-auth` because the token is memory-only. Drive files are found by `appProperties` scoped by `root` (the root folder id; two folders of the same vault coexist during a mode switch), never by path, and uploads check existence first (idempotent). The pull cursor is a Drive `startPageToken`; without relevant feed changes the store skips relisting (full relist every 10 min). Encryption (`shared/crypto.ts`, `domain/encryption.ts`): the vault key is wrapped in `encryption.json` by a password slot and a recovery-code slot (PBKDF2 600k); HKDF gives an AES-GCM content key and an HMAC object-id key, kept per device as non-extractable `CryptoKey`s in device pref `driveKeys:<folderId>`; encrypted files are `MNE1`+IV+GCM with AAD `vaultId|scope|id`; there are no `readable/` copies; the store refuses to run when the root's `encrypted` flag doesn't match its cipher. A mode switch creates a new folder and pushes everything, then marks the old root `supersededBy`; other devices get `not-found` and `relocateDrive` rebinds them to the `supersededBy` target (phase `needs-key` if the new folder is encrypted). Never publish in plaintext without explicit consent (security audit 2026-10-13, H01): encrypted → plain relocation stops in phase `needs-confirm` (accept or re-encrypt into a new folder), and `connectDrive` with `mode: 'encrypted'` returning `existingPlain` has published nothing yet. `encryption.json` is bounded before any PBKDF2 (H06); future-version revisions must pass `revisionEnvelopeSchema` (H05); scenes drop non-`data:` files and `iframe` `generationData`, and embeddables are disabled (H02). The audit report and its response (pending items, owner decisions) are kept outside the repo (`auditoria-*/` is gitignored). Drive modules + GIS are dynamically imported in `app/composition/remotes.ts` only after the owner picks plain/encrypted and confirms its warning (two clicks: confirm loads GIS, «Continuar con Google» opens the popup in its own gesture); adapters are only wired in `src/app/composition/` (ESLint enforces it). A vault opened from a folder must not get the auto-created first canvas. E2E tests replace `showDirectoryPicker` with an OPFS directory.

Portability (phase 5): pure rules in `application/portability.ts` (raster budget 16.7 Mpx = Safari's canvas limit, PDF page plan, safe filenames, `.excalidraw` import analysis, Markdown ↔ note, folder tree export); engine-side work in `adapters/excalidraw/exporters.ts`; UI in `features/canvas/ExportDialog.tsx` and `app/importExport.ts`. Imports always create new documents in a single `save` revision (`VaultService.importNote`/`importCanvas`, which verifies asset hashes) and report what was dropped — never import remote/embedded web content. jsPDF is dynamically imported; its optional deps are removed via `pnpm-workspace.yaml` overrides and the `jspdf-optional` plugin in `vite.config.ts` resolves only jsPDF's imports of them to `src/vendor/jspdfOptional.ts` (dompurify must keep resolving normally for Mermaid). `tests/unit/accesibilidad.test.ts` enforces WCAG AA contrast of the CSS tokens and es/en key parity (every literal `t('…')` key must exist).

IndexedDB schema v1 (`adapters/indexeddb/db.ts`) already declares tables for future features (remoteFiles, linkIndex, searchDocuments, controls…) to avoid migrations. Vault and device identity live in `deviceSettings` (keys `vault`, `device`); device preferences use `pref:<key>` (e.g. the last opened document).

### Privacy/network constraints

No external requests without Drive enabled (e2e tests assert this, including that cancelling the mode/RN-12 dialog contacts nothing): Excalidraw fonts are self-hosted via `window.EXCALIDRAW_ASSET_PATH`, the main menu omits external links, Markdown preview disables raw HTML and turns images into links, `aline://` (and legacy `mindnote://`) links are intercepted in-app. `public/_headers` holds the enforcing CSP (plan 9.1) with the exact Google endpoints (GIS, googleapis, oauth2 revoke) and `Referrer-Policy: strict-origin-when-cross-origin` (GIS rejects no-referrer); `tests/e2e/csp.spec.ts` serves the app with that policy and fails on any violation. No `'unsafe-eval'`: domain code imports zod only from `domain/zod.ts` (`jitless`, so zod never probes `Function`), and the engine patch drops the esm.sh font fallback when `EXCALIDRAW_ASSET_PATH` is set.
